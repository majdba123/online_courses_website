# EZ Medicine — منصة الدورات الطبية

[English](README.md) | [العربية](README_AR.md)

> منصة تعليم طبي مبنية باستخدام Laravel لإدارة الدورات المدفوعة، الأطباء، محتوى الفيديو المحمي، حسابات الطلاب، التقييمات، المفضلة، الطلبات، ولوحة الإدارة.

## نظرة عامة

EZ Medicine هي منصة تعليم طبي عبر الإنترنت مخصصة لتنظيم وتقديم الدورات الطبية المدفوعة. يجمع المشروع بين واجهة عامة لعرض الدورات وتجربة طالب مسجّل وبين لوحة إدارة محمية لإدارة المحتوى والطلبات والمستخدمين.

التطبيق الرئيسي موجود حالياً داخل مجلد [`EZM/`](EZM/)، وتم الحفاظ على هذه البنية كما هي لتجنب كسر أي مسارات أو افتراضات تشغيلية موجودة مسبقاً.

المنصة تغطي رحلة التعلم بشكل مترابط: استعراض الدورات، ربط الدورات بالأطباء، التسجيل والتحقق من البريد، إنشاء طلب دورة، مراجعة الطلب من الإدارة، الوصول المشروط للمحتوى، فيديوهات الدروس، المفضلة، التقييمات، سجل الطلبات، وإدارة المحتوى من لوحة التحكم.

## أهم القدرات

### تجربة الطالب

تتضمن الواجهة العامة وتجربة المستخدم المسجّل:

- استعراض الدورات الطبية؛
- عرض أسعار الدورات ومعلومات الطبيب؛
- التسجيل وتسجيل الدخول؛
- التحقق من البريد الإلكتروني؛
- تسجيل الدخول باستخدام Google عبر Laravel Socialite؛
- الملف الشخصي؛
- الدورات المفضلة؛
- تقييم الدورات والتعليقات؛
- سجل الطلبات؛
- سجل الدورات المشتراة / المسجّل بها؛
- صفحات فيديو محمية؛
- إرسال الاستفسارات؛
- أقسام تعريفية مثل المزايا والأهداف والإنجازات والأسئلة الشائعة وصفحة من نحن.

الصفحة الرئيسية تعرّف EZ Medicine كمنصة تعليم طبي متخصصة وتعرض الدورات والأطباء والأسعار وآراء المتعلمين والأسئلة الشائعة.

## آلية الوصول إلى الدورات المدفوعة

المحتوى ليس مكتبة فيديو مفتوحة بدون قيود.

الآلية الموجودة حالياً تعتمد على المستخدم المسجّل وحالة الطلب:

1. يختار المستخدم الموثّق دورة؛
2. يرسل طلب شراء مع صورة إثبات الدفع؛
3. يتم حفظ الطلب مع المستخدم والدورة؛
4. يراجع المسؤول الطلب ويغيّر حالته؛
5. يتم التحقق من حالة الطلب عبر Middleware خاص؛
6. يحصل المستخدم المصرح له على الوصول إلى محتوى الدورة والفيديوهات.

لذلك الوصف الأدق للمشروع هو منصة دورات مدفوعة تعتمد على موافقة الإدارة للوصول إلى المحتوى، وليس نظام دفع إلكتروني آلي بالكامل عبر Payment Gateway.

## نموذج بيانات الدورات

الدورة مرتبطة بعدة عناصر داخل النظام، منها:

- الطبيب / المحاضر؛
- الخصومات؛
- الطلبات؛
- الفيديوهات؛
- المفضلة؛
- التقييمات.

كما تستخدم نماذج الدورات والمستخدمين حالياً معرفات UUID يتم إنشاؤها عند إضافة السجل.

## لوحة الإدارة

منطقة `/dashboard` محمية بالمصادقة وAdmin Middleware.

تشمل العمليات الإدارية الموجودة في الكود إدارة:

- محتوى الموقع؛
- الأطباء؛
- الخصومات والعروض؛
- الدورات؛
- الفيديوهات؛
- الاستفسارات؛
- التقييمات؛
- المستخدمين؛
- المزايا؛
- الأسئلة الشائعة؛
- الأهداف؛
- الإنجازات؛
- الطلبات.

وتتضمن عدة أقسام إمكانيات بحث وتعديل وحذف وإضافة حسب المورد.

## حماية الفيديو والمحتوى

تستخدم مسارات المحتوى التعليمي Middleware للتحقق من تسجيل الدخول، والتحقق من البريد، وحالة الطلب/الدفع قبل السماح بالوصول إلى بعض صفحات الفيديو.

يوجد أيضاً تدفق لإنشاء رابط مؤقت للوصول إلى الفيديو ضمن التطبيق الحالي. هذا جزء من التنفيذ الحالي، لكنه يحتاج لاحقاً إلى Audit أمني وتشغيلي مستقل قبل اعتباره نظام DRM قوي أو حماية مطلقة للمحتوى.

## المصادقة

يشمل النظام الحالي:

- صلاحيات منفصلة للوصول إلى لوحة الإدارة.

## التشغيل للتطوير

من داخل مجلد التطبيق:

```bash
cd EZM
composer install
npm install
npm run dev
```

كما يحتاج Laravel إلى إعداد البيئة المحلية المعتاد مثل ملف Environment، وApplication Key، وقاعدة البيانات، وتنفيذ الـmigrations حسب البيئة.

ولإنشاء نسخة Production من ملفات الواجهة:

```bash
npm run build
```

## الاختبارات

المشروع يحتوي على PHPUnit وبيئة اختبارات Laravel، لكن توثيق المستودع لا يعتبر بحد ذاته إثباتاً أن جميع الاختبارات أو الـruntime تعمل حالياً بدون مشاكل.

قبل اعتبار المشروع Verified Production Baseline يجب تشغيل وفحص الـmigrations، المصادقة، الطلبات، حماية الفيديو، وعمليات المستخدم والإدارة بشكل فعلي.

## ملاحظات أمنية

عدة مسارات محمية بالمصادقة، التحقق من البريد، Admin Middleware، وفحص حالة الطلب. لكن حماية الفيديو على مستوى التطبيق لا تعني حماية مطلقة ضد تسجيل أو نسخ المحتوى.

يجب إبقاء مفاتيح OAuth والـsecrets وإعدادات Production خارج Source Control.
